**1. Cluster C — Specification-Layer** *(execute within 30 days)*
Lowest competition in the entire architecture. One well-structured page with LocalBusiness + Service schema, a downloadable spec sheet PDF, and architect-appropriate language will rank within 60 days for uncontested terms. Revenue per conversion is highest of any cluster.

**2. Cluster D — Problem-Aware** *(execute within 45 days)*

**3. Cluster B — Location (Johannesburg)** *(execute within 60 days)*
Highest revenue volume. JHB page needs: suburb list (Sandton, Midrand, Fourways, Bryanston, Morningside), project image gallery, LocalBusiness schema with service area. Builds on the existing homepage domain authority.

## Implementation Notes

### URL Architecture
Recommend flat structure: all landing pages at root level (`/artificial-grass-johannesburg/`) rather than nested (`/locations/johannesburg/`). GitHub Pages serves flat HTML files cleanly — create each as a separate `.html` file (`artificial-grass-johannesburg.html`) matching the slug.

### Internal Linking Priority
Every city page → links to `/commercial-artificial-turf-specification/` (spec-layer page)  
Every city page → links to `/water-saving-artificial-grass/` (problem-aware page)  
Homepage → links to all 3 city pages + spec-layer page in nav or section cards  

### Schema Prep
Each landing page needs its own LocalBusiness schema with the city-specific `areaServed` field. Phase 03 will produce the full JSON-LD blocks.

### Quick Win: FAQ Schema on Homepage
Add FAQPage schema to `index.html` answering the top 3 long-tails from the table above. Zero new content required — pull from existing copy. Can rank in Google's "People also ask" box within 2-4 weeks.
